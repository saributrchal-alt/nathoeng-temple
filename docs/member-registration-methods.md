# เพิ่มสมาชิก: เจ้าหน้าที่ / เครื่องอ่านบัตร

หน้าเพิ่มสมาชิกเริ่มต้นด้วยสองปุ่ม ฟอร์มเต็มปรากฏหลังเลือก **กรอกโดยเจ้าหน้าที่**; มีชื่อไทย/อังกฤษ เลขบัตรหรือหนังสือเดินทาง วันเกิด ประเทศ ที่อยู่แยกช่อง รูปสมาชิก และบัญชีเข้าใช้งาน นำเข้า JSON รูปแบบ `saributr-card-v1` ของแอป 1.4 ขึ้นไปได้ และต้องตรวจทานก่อนบันทึก

**เครื่องอ่านบัตร — Desktop:** เปิดแอปอ่านบัตรเดิม อ่านบัตร แล้วกดรับข้อมูลภายใน 2 นาที หรือเลือก JSON ที่ส่งจากเครื่องอ่าน เว็บเติมฟอร์มเต็มให้ตรวจทานแล้วบันทึก

**เครื่องอ่านบัตร — Android:** ติดตั้ง APK 1.5.6 ที่ `public/downloads/Saributr-Card-Reader-1.5.6-Android.apk`; กดอ่านจากเว็บ เปิด native app อ่าน/ตรวจข้อมูล กดยืนยันแล้วกลับเว็บเพื่อบันทึก โดยไม่เลือกไฟล์ JSON ดู `card-reader/android/README.md`

## เปิดใช้งาน

1. รัน `supabase/walkin-member-full-registration.sql` ใน Supabase ของ **watt.nathoeng.com** หลัง migrations สมาชิกเดิมตามหัวไฟล์
2. Deploy ชุดนี้หลัง SQL สำเร็จ API ใช้ RPC ใหม่เพื่อบันทึกสมาชิก ชื่ออังกฤษ ที่อยู่ ประเทศ บัญชีเข้าใช้ และการตรวจบัตรในธุรกรรมเดียว ไม่มี fallback ที่ทิ้งข้อมูลฟอร์มบางช่อง
3. ติดตั้ง Android APK 1.5.6 ทับ 1.5.3–1.5.5 ที่เครื่องของผู้ดูแล และทดลองเครื่องอ่าน/OTG/Chrome จริง

เมื่อพบเลขบัตรหรือชื่อสมาชิกเดิม จะโหลดข้อมูลบัญชีเดิม การบันทึกใช้ API แก้ไขเดิมและไม่สร้างซ้ำ รหัสผ่านเดิมคงอยู่หากเว้นช่องรหัสผ่านใหม่ การ reload รายชื่อหลังบันทึกไม่ unmount หน้าผลสำเร็จ เพื่อให้เจ้าหน้าที่ได้เห็นข้อมูลเข้าใช้งานที่สร้างใหม่

ถ้า RPC หรือ migrations ที่ต้องใช้ยังไม่พร้อม API ตอบ 503 และไม่มีข้อมูลสมาชิกที่บันทึกเพียงบางส่วน การลงทะเบียนด้วย API รูปแบบเดิมยังใช้ RPC เดิม

## ผลทดสอบ

- Vite production build ผ่าน; lint เฉพาะโค้ดใหม่ผ่าน (AdminDashboard มี warnings เดิม)
- `node --test tests/card-verification.test.js tests/walkin-registration.test.js`: การส่งทุกช่องใน RPC เดียว การตรวจข้อมูล/สิทธิ์/หลักฐานบัตร การรองรับ passport/country และข้อความเมื่อยังไม่รัน SQL
- React/jsdom: หน้าเริ่มต้นไม่แสดงฟอร์ม, ฟอร์มเจ้าหน้าที่ครบ, ตรวจทานก่อนบันทึก, ป้องกันกดซ้ำ, JSON/Desktop import, Android callback/autosave, ปฏิเสธ callback ที่ไม่ได้เริ่มจากเว็บ
- PostgreSQL/PGlite รัน migrations เดิมและใหม่: เก็บข้อมูลครบ, รหัสผ่าน/การตรวจบัตร, reject ข้อมูลซ้ำ, rollback ทั้งสมาชิกเมื่อขั้นตอนที่อยู่/บัญชีล้มเหลว, สิทธิ์ RPC เฉพาะ service_role
- Android: compile, CCID/ThaiCard/loopback bridge tests, APK verification และ signing certificate ตรงกับ 1.5.3

ยังไม่มีการสร้างสมาชิกจริงในการทดสอบ และยังไม่มีผลทดสอบเครื่องอ่านจริงของ flow มือถือใหม่

## ส่งข้อมูลมือถือกลับ Chrome โดยตรง (1.5.6)

แอปส่ง JSON เข้ารหัส AES-256-GCM ใน URL fragment กลับ Chrome เว็บรับข้อมูลก่อนอ่าน route แล้วนำ fragment ออกจาก URL ถอดรหัสด้วยกุญแจสุ่มของคำขอที่เริ่มในเบราว์เซอร์นี้เท่านั้น และตรวจ nonce/อายุบัตร/ข้อมูลก่อนบันทึก ไม่มีการเรียก localhost ในช่องทางใหม่นี้ จึงไม่ต้องขอสิทธิ์เครือข่ายภายในเครื่องเพื่อรับบัตร

ติดตั้ง APK **1.5.6** ทับรุ่นเดิม รีเฟรชเว็บ แล้วกดอ่านใหม่ ใช้ Chrome ที่เริ่มคำขอเดิม หากเห็น `[CARD_RETURN_MISSING]` ให้ตรวจรุ่นแอปและเริ่มอ่านใหม่ ไม่ต้องรัน SQL เพิ่มสำหรับการอัปเดตนี้ Desktop ใช้ช่องทางเดิม

ทดสอบ ciphertext จาก Android Java กับ Web Crypto จริงผ่าน รวมถึงชื่อไทยและรูปบัตรสังเคราะห์ 5100 ไบต์ ทดสอบการแก้ไขข้อมูล/nonce ผิด/ขนาดเกิน/หมดอายุ/กุญแจผิดแล้วปฏิเสธโดยไม่ fallback ไป localhost การคืน route และการ autosave ครั้งเดียวใน React StrictMode ผ่าน ผลเครื่องอ่านจริงบนมือถือยังรอผู้ดูแลยืนยัน
